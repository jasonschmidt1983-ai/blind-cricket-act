# Blind Cricket ACT — approved static website plan

## Approved scope
The user selected GitHub Pages only on 16 November 2026: public information pages, without online registration, private admin or sensitive-data collection. This supersedes the earlier full-stack implementation and all GoDaddy-hosting assumptions. GoDaddy remains the registrar for blindcricket.com.au; GitHub Pages is the intended host. No online forms, uploads, admin/login, database, token processing or payment collection are included. Registration, volunteering, sponsorship and donations become explanatory information/enquiry pathways, never simulated submissions. Do not request personal/medical details through GitHub issues or commit them to source.

Build the entire public information architecture in the existing React/TypeScript/Vite project: homepage; Play Cricket and Get Started, Register Your Interest (enquiry guidance only), Training & Locations, Membership & Fees (information only), Accessibility & Support, FAQ; Programs & Pathways and Albury Program, Junior Program, Women & Inclusion, Multicultural Program, Community Programs, Player Pathways; Fixtures & Results; News & Stories with public editorial pages; Support Us (donations, volunteer and sponsorship enquiry information); About; Contact; Governance & Policies; footer-only Report a Safety Issue; photo credits/accessibility statement.

Homepage preserves the supplied headline “Blind cricket is more than meets the eye.”, subheading “A game shaped by sound, teamwork and trust. Open to anyone who is blind or has low vision.”, supporting text “No experience needed. Join an inclusive cricket community in Canberra and the surrounding region.” and Register to play, Volunteer, Donate pathways. Four entirely clickable image tiles: Play Cricket, Come and Try, Volunteer, Support Us. Include What is Blind Cricket, Upcoming Training & Matches, News & Stories, Community & Inclusion, Sponsors & Partners. Use meaningful real blind cricket photographs with descriptive alt text; no artificial disability imagery, stock corporate poses, empty grounds, redundant captions, carousel or autoplay.

Do not invent live fixtures, fees, scores, testimonials, sponsor endorsements or approved club policies. Use useful enquiry and awaiting-confirmation states for absent operational data. PACE Farms support for the multicultural program is included as supplied. Partners not established as club sponsors must be presented as cricket/inclusion organisations, not falsely endorsed sponsor logos. Add static brand partner grid and Become a Sponsor pathway. Photo ownership/reuse permission needs confirmation before final public launch; source credit alone is not permission.

## Design
Reuse the supplied navy #002855, white #FFFFFF and yellow #FFC72C. Contemporary sports editorial design with a split navy hero and large action photograph, bold Barlow Condensed headlines with italic yellow emphasis, Barlow body text, an optimistic yellow welcome strip and generous white-space sections. Trustworthy, active and warm. Small uppercase eyebrow labels, cricket seam/sound-wave motifs and expressive arrow links are signature details. Use the official owner-supplied Blind Cricket ACT logo (supplied 16 November 2026), retaining all artwork and lettering. Logo at top left links home; footer logo bottom right. Major sections contain meaningful photographs. Cards may use grids where requested, while text/image sections use asymmetric editorial layouts.

Interactions are purposeful: full-card links, focus states, keyboard mobile-menu controls, native FAQ disclosures, a browser-only local search for public content, accessible filter buttons for fixtures/news and non-intrusive saved accessibility preferences (text size and high contrast only, no personal data). Short 150ms hover transitions only, disabled for reduced-motion users. All content visible without animations.

## Accessibility
Target WCAG 2.2 AA with one H1/page, logical headings, semantic landmarks, skip to content, visible high-contrast keyboard focus, descriptive links and alt text, no autoplay audio/video or CAPTCHA, zoom-friendly reflow and mobile touch targets. No data-entry forms; public-content search is not a submission. Use labels and live announcements for interactive search/filter status. Support reduced motion and native keyboard behaviour. NVDA/JAWS/VoiceOver/TalkBack conformance requires manual assistive-technology review; don't present automated checks as certification.

## Static implementation and serving
React renders public pages from shared static content. Generate real per-route HTML at build time using react-dom/server, preserving crawlable content, page-specific metadata and canonical URLs at https://blindcricket.com.au, with matching sitemap/robots. Generate route subdirectory index files and a real 404.html for GitHub Pages. Browser hydration adds menus/search/filter/accessibility interactions; navigation uses ordinary anchors so pages still work without JavaScript. No API or Manus auth/storage dependency in the published site.

Use small optimised public photography files inside the repo to make the GitHub-hosted build self-contained; Manus-only /manus-storage addresses must not be relied on from GitHub Pages. Keep the source image downloads copied into the project working assets directory, with credits. Pin existing pnpm version. Build site into docs/ and use branch publishing from main/docs with .nojekyll and CNAME, avoiding GitHub Actions on the managed canonical repository. Preview uses pnpm dev:static at port 3000; the project already provisioned server/database capabilities before the scope changed and they cannot be switched off through the platform, but they are unused and never part of the GitHub Pages deployment. Do not start the server, migrate tables or enable Stripe.

Save a Manus checkpoint, then use the owner-confirmed platform workflow to connect a new private GitHub repository. GitHub Pages on a private repository requires an eligible GitHub account plan; changing source visibility to public requires owner consent and should not expose planning/private/internal data. Check repository/account availability after connection. Configure/verify the domain in GitHub before any GoDaddy DNS changes, preserve email records, and enable HTTPS when certificate setup allows. Publication readiness is distinct from domain connection; do not claim live until verified.

## Structure
`shared/siteData.ts` owns navigation, page content, story metadata and search index. `client/src/components/SiteLayout.tsx` owns logo/header/footer/search/accessibility controls. `client/src/pages/Home.tsx` owns the complete editorial homepage. `client/src/pages/InfoPage.tsx` renders public sections/subpages, FAQ/pathways, fixtures/news filtering and sensible not-yet-confirmed information. `client/src/App.tsx` resolves the public route. `client/src/main.tsx` hydrates static markup without API providers. `client/src/index.css` owns brand/responsive/accessibility styles. `scripts/build-pages.tsx` generates all per-route HTML and deployment files after Vite compilation. `client/public/` contains optimised site imagery/favicon/route manifest. `docs/` is the self-contained committed GitHub Pages publication directory. `LAUNCH.md` explains the excluded full-stack features and outstanding source permissions, content approval, GitHub eligibility and DNS/HTTPS checks.
